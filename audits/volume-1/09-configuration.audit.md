## 1. Concept hierarchy audit

**PASS.**

The chapter keeps the four relevant levels distinct:

- $x$: one domain point
- $n(x)$: one field value
- $n$ or $n(\cdot)$: the full field
- one configuration: one allowed full-field assignment in the candidate field model

It also correctly explains that calling the same full assignment a `field` or a `configuration` emphasizes different roles rather than creating two separate physical objects.

## 2. Configuration-space point boundary

**PASS.**

The chapter correctly prepares the next abstraction: a full configuration can later be treated as one point of configuration space. It repeatedly blocks the common confusion

$$
\text{domain point}\neq\text{configuration-space point}.
$$

No claim is made that configuration space is literally a low-dimensional physical room.

This chapter explicitly restricts its use to the candidate n-field assignment, so this is **non-blocking**.
